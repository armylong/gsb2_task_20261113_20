# 本地压缩包安全检查工具

接收外部素材包（zip / tar / tar.gz）后，**先在不落地任何成员内容的前提下完成安全检查**，
看清目录穿越、覆盖、链接逃逸、压缩炸弹等风险，再由用户勾选确认安全的普通文件释放。
纯 Python 标准库后端 + 原生 JavaScript 前端，无第三方依赖、无账号、无外部网络访问，
服务只监听本机回环地址 `127.0.0.1`。

## 一、安装与启动

要求 Python 3.9+（开发与验证环境为 3.12），无需 `pip install` 任何依赖。

```bash
# 在仓库根目录执行
python3 run.py
# 看到“压缩包安全检查工具已启动：http://127.0.0.1:8765”后，浏览器打开该地址
```

可选环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `SAFEARCH_PORT` | `8765` | 监听端口 |
| `SAFEARCH_DATA_DIR` | `./data` | 上传原件/任务/释放结果的数据目录 |
| `SAFEARCH_HOST` | `127.0.0.1` | 监听地址，不建议改成对外地址 |
| `SAFEARCH_MAX_UPLOAD` | `2147483648` | 单次上传体积硬上限（字节） |

停止服务：终端按 `Ctrl+C`。

## 二、运行自动化测试

全部测试使用标准库 `unittest`，测试数据放在系统临时目录，不污染仓库：

```bash
# 端到端安全测试（起真实 HTTP 服务，16 个场景）
python3 -I tests/test_security.py

# 路径分析器单元测试（11 个边界组合）
python3 -I tests/test_analyzer.py
```

`-I` 为隔离模式：忽略当前目录与环境变量中的 `PYTHONPATH`，
防止压缩包中可能存在的同名模块（如 `json.py`）被解释器加载。

测试覆盖：危险包不在释放目录外留文件、压缩比例/条目/大小超限中止、
损坏包不拖垮服务、失败释放整批回滚、跨批次下载隔离与下载地址越权拒绝、
正常中文包检查与释放全流程、重启后历史记录恢复等。

## 三、页面使用

1. 左侧设置四项限制：**条目数上限、单文件释放大小、总释放大小、压缩比例上限**；
2. 选择本地 zip/tar/tar.gz 上传，或直接点击内置的 8 个本地演示包；
3. 右侧查看每个条目的原始名称、类型、声明大小、实际大小、目标相对路径与风险原因，
   可按危险/警告/可释放筛选，点击风险代码查看详情与冲突涉及的对端条目；
4. 扫描完成后，只有标记为“安全”的普通文件可勾选，点击“释放勾选的安全文件”；
5. 释放成功后可打包下载本批文件，也可随时下载该包的 JSON 检查报告。

页面状态实时反映：已上传 → 检查中 → 检查完成/检查失败 → 释放中 → 释放完成/释放失败。
刷新页面或重启服务后，历史任务与结论仍在。

## 四、安全模型（纵深防御）

### 1. 扫描阶段只读、不落地

* 统一只读访问层 `app/archiveio.py` 流式遍历 zip/tar/tar.gz，
  成员内容仅进入内存分块计算 SHA-256，不写入释放目录或任何其他位置；
* 损坏包、不支持格式收敛为任务级错误，异常不会让服务进程退出。

### 2. 路径与结构检查（`app/analyzer.py`，纯字符串运算）

* 绝对路径、Windows 盘符/UNC 路径、反斜杠分隔符绕过、`..` 目录穿越；
* 规范化后**重名**、仅**大小写不同**的落点冲突、**文件与目录冲突**，
  风险详情中记录冲突双方的序号与原始名称；
* 符号链接/硬链接指向目录外，以及“先放看似正常的链接、后续普通文件借链接写到外面”
  的组合攻击（含链接循环检测）；
* 字符设备/块设备/FIFO 等特殊文件、嵌套压缩包（仅提示，不自动递归解包）。

### 3. 限制不只信声明（`app/limits.py`）

包内声明大小只用于预判；真正读取成员时按 64KiB 分块累计**真实字节**，
实时复核单文件、总释放大小与真实压缩比例，任一项超限立即中止并注明触发项。

### 4. 释放阶段服务端强制（`app/extractor.py`）

* 前端勾选只作交互用途；服务端只认扫描结论：风险条目、符号链接、硬链接、
  特殊文件、非普通文件即使被直接写进请求也一律拒绝；
* 每次释放生成独立批次目录，先写同目录暂存区，全部成功后才原子切换为正式目录；
* 中途损坏、超限、写入失败、摘要不一致都会**整批回滚**，删除暂存区，不留半成品；
* 每个目标写盘前再次独立做路径规范化与根目录包含校验，文件以 `xb` 模式创建，绝不覆盖；
* 必要的父目录自动建立，但目录/链接条目本身不会被释放。

### 5. 下载隔离

* 打包下载与单文件下载都校验批次归属：只能访问本任务下**成功释放**的批次；
* 单文件路径再次做根目录包含校验并拒绝符号链接，`../` 等穿越尝试返回 404，
  无法借下载地址读取批次外文件。

## 五、内置演示包

服务启动时在数据目录 `data/demos/` 内现建（幂等），仅含危险**名称/结构**的文本数据，
不含可执行脚本、不访问网络：

| key | 场景 |
| --- | --- |
| `normal` | 正常中文文件名与目录结构 |
| `traversal` | `../../` 目录穿越 |
| `absolute` | `/` 开头绝对路径（tar.gz） |
| `backslash` | 反斜杠伪装分隔符绕过 |
| `duplicate` | 重名、大小写冲突、文件/目录冲突 |
| `symlink` | 符号链接 + 后续文件组合逃逸（tar.gz） |
| `bomb` | 高压缩比内容，触发比例上限 |
| `corrupt` | 魔数正确但中央目录被截断的损坏 zip |

## 六、代码结构

```
app/
  config.py       数据目录、硬限制边界、默认限制
  limits.py       限制参数钳制与真实字节 SizeTracker
  archiveio.py    zip/tar/tar.gz 统一只读访问层（不落地）
  risks.py        风险代码、中文说明与严重级别
  analyzer.py     路径规范化、冲突树、符号链接组合分析
  scanner.py      扫描编排：静态分析 + 有界真实读取 + 摘要
  extractor.py    事务化安全释放、回滚、下载路径解析
  jobs.py         任务状态机、JSON 持久化、并发互斥
  demo_builder.py 本地演示包生成
  server.py       标准库 HTTP 服务、multipart 流式上传、全部 API
static/           原生 JS 单页（index.html / app.js / styles.css）
tests/            自动化测试
run.py            启动入口
```

## 七、主要 HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/jobs` | multipart 上传压缩包并开始扫描（限制参数同表单提交） |
| `GET` | `/api/jobs` | 任务列表（刷新后恢复历史） |
| `GET` | `/api/jobs/{id}` | 任务详情与全部条目结论 |
| `POST` | `/api/jobs/{id}/extract` | 提交 `{"indexes": [...]}` 释放，服务端二次安全复核 |
| `GET` | `/api/jobs/{id}/report` | 中文 JSON 检查报告（含每次释放的真实成败） |
| `GET` | `/api/jobs/{id}/download?release_id=...` | 下载本批成功释放文件的 zip |
| `GET` | `/api/jobs/{id}/files/{rel}?release_id=...` | 批次内单文件下载（越权返回 404） |
| `POST` | `/api/demos/{key}/load` | 加载本地演示包 |
| `GET` | `/api/demos` | 演示包清单 |

## 八、报告内容

JSON 报告（中文键）包含：文件摘要与扫描汇总、实际生效的限制参数、
每个条目的原始名称、目标相对路径、类型、声明/实际大小、SHA-256、
风险代码与中文原因、释放结果，以及每次释放记录。
释放失败会如实保留失败记录与原因，后续重试不会把历史失败改写成成功。
